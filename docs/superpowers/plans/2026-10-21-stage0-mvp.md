# job-apply-tracker — Stage 0 (skeleton) + Stage 1 (MVP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working Django 5.2 job-application tracker the author uses daily: inbox of vacancies, applications with event timeline and attachments, "needs attention" dashboard — on PostgreSQL, fully tested, with security CI.

**Architecture:** Three apps by domain: `accounts` (custom User), `tracker` (all domain models, CBVs, forms, templates), `api` (Stage 2, not in this plan). Multi-user isolation via `owner` FK + queryset filtering; no open registration. Status changes write timeline events through a model method (no signals). "Needs attention" computed by a custom QuerySet.

**Tech Stack:** Python 3.12 (`py -3.12`, global env — no venv, per user's machine policy), Django ≥5.2,<5.3, psycopg[binary] 3.x, PostgreSQL 17 (docker compose), pytest-django, factory_boy, pytest-cov, ruff, bandit, pip-audit, gitleaks (CI), Pico.css (classless, vendored static file).

**Spec:** `docs/superpowers/specs/2026-10-14-job-apply-tracker-design.md` (RU translation alongside; EN canonical)

## Global Constraints

- Django pinned `>=5.2,<5.3` (5.2 LTS). Python commands always `py -3.12 ...` (bare `python` is an empty 3.14 — see user CLAUDE.md).
- Custom User lands **before the first migration of any app**.
- Every domain model: `owner = FK(settings.AUTH_USER_MODEL)` + `created_at`/`updated_at`.
- All list views covered by `assertNumQueries`.
- Coverage gate: `--cov-fail-under=85` (CI). TDD per task.
- `TIME_ZONE = "Europe/Bratislava"`, `USE_TZ = True`, `LANGUAGE_CODE = "en"` (i18n is Stage 3).
- Active application statuses (for needs-attention): exactly `applied`, `replied`.
- Attachment validation: extensions `.pdf .doc .docx .odt .txt`, max 5 MB.
- No secrets in code or commits; dev DB password lives only in `docker-compose.yml`/`dev.py` and is throwaway.
- Windows gotcha: if a fresh `.pyd` import fails with "DLL load failed … политика управления приложениями" — that's Smart App Control; install the previous minor version of the package (see user CLAUDE.md), do not debug Python.
- Branch/PR workflow, small commits. Three PRs: `feature/skeleton` (Tasks 1–3), `feature/mvp-models` (Tasks 4–8), `feature/mvp-ui` (Tasks 9–14).
- **Learning project:** each task has a "Mentor" line — what concept to explain first and who writes the key code (user = Алексей writes after explanation, Claude reviews; otherwise Claude writes with explanations).

## Review Focus

Spec-implied behaviors most likely to bite, each pinned to a test in the owning task:

1. An application with **zero events** must still show in "needs attention" (fallback to `applied_at`), else silent follow-up loss — Task 8.
2. **Cross-owner access**: foreign object by pk → 404; list views and form dropdowns never leak another user's rows — Tasks 10, 11, 12.
3. **Attachment abuse**: oversized (>5 MB) or disallowed-extension file rejected with a form error, not a 500 — Task 7.
4. **Double "Applied"** on a vacancy that already has an application must not crash on the OneToOne (IntegrityError) — redirect to the existing application — Task 11.
5. **VacancyForm company dropdown** limited to the owner's companies; posting a foreign company id is a validation error, not a saved row — Task 11.
