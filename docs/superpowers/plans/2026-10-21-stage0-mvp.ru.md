# job-apply-tracker — план реализации этапа 0 (каркас) + этапа 1 (MVP)

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ САБ-СКИЛЛ: superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans — выполнять план задача за задачей. Шаги размечены чекбоксами (`- [ ]`).

> Это перевод [английского плана](2026-10-21-stage0-mvp.md) для удобства
> автора. При расхождениях главный — английский файл.

**Цель:** Рабочий Django 5.2 трекер откликов, которым автор пользуется ежедневно: входящие вакансии, отклики с лентой событий и вложениями, дашборд «требует действия» — на PostgreSQL, полностью покрыт тестами, с security-CI.

**Архитектура:** Три приложения по доменам: `accounts` (кастомный User), `tracker` (все доменные модели, CBV, формы, шаблоны), `api` (этап 2, не в этом плане). Multi-user изоляция через FK `owner` + фильтрацию queryset'ов; без открытой регистрации. Смена статуса пишет событие в ленту через метод модели (без сигналов). «Требует действия» вычисляется кастомным QuerySet.

**Стек:** Python 3.12 (`py -3.12`, глобальное окружение — без venv, по политике машины пользователя), Django ≥5.2,<5.3, psycopg[binary] 3.x, PostgreSQL 17 (docker compose), pytest-django, factory_boy, pytest-cov, ruff, bandit, pip-audit, gitleaks (CI), Pico.css (classless, лежит в static).

**Спека:** `docs/superpowers/specs/2026-10-14-job-apply-tracker-design.md` (рядом русский перевод; канон — английский)

## Глобальные ограничения

- Django закреплён `>=5.2,<5.3` (5.2 LTS). Python-команды всегда `py -3.12 ...` (голый `python` — пустая 3.14, см. CLAUDE.md пользователя).
- Кастомный User появляется **до первой миграции любого приложения**.
- Каждая доменная модель: `owner = FK(settings.AUTH_USER_MODEL)` + `created_at`/`updated_at`.
- Все списочные вьюхи покрыты `assertNumQueries`.
- Порог покрытия: `--cov-fail-under=85` (CI). TDD в каждой задаче.
- `TIME_ZONE = "Europe/Bratislava"`, `USE_TZ = True`, `LANGUAGE_CODE = "en"` (i18n — этап 3).
- Активные статусы отклика (для «требует действия»): ровно `applied`, `replied`.
- Валидация вложений: расширения `.pdf .doc .docx .odt .txt`, максимум 5 МБ.
- Никаких секретов в коде и коммитах; dev-пароль БД живёт только в `docker-compose.yml`/`dev.py` и одноразовый.
- Грабли Windows: если импорт свежего `.pyd` падает с «DLL load failed … политика управления приложениями» — это Smart App Control; ставить предыдущую минорную версию пакета (см. CLAUDE.md), а не дебажить Python.
- Ветки + PR, маленькие коммиты. Три PR: `feature/skeleton` (задачи 1–3), `feature/mvp-models` (4–8), `feature/mvp-ui` (9–14).
- **Учебный проект:** у каждой задачи строка «Ментор» — какую концепцию объяснить сначала и кто пишет ключевой код (user = Алексей пишет после объяснения, Claude ревьюит; иначе пишет Claude с объяснениями).

## Фокус ревью

Поведение, которое спека подразумевает и которое вероятнее всего укусит; каждый пункт пришпилен к тесту в своей задаче:

1. Отклик **без единого события** обязан попадать в «требует действия» (fallback на `applied_at`), иначе follow-up тихо теряется — задача 8.
2. **Доступ к чужому**: чужой объект по pk → 404; списки и выпадашки форм никогда не показывают чужие строки — задачи 10, 11, 12.
3. **Злоупотребление вложениями**: слишком большой (>5 МБ) или с запрещённым расширением файл отклоняется ошибкой формы, а не 500 — задача 7.
4. **Повторное «Откликнулся»** на вакансию с существующим откликом не должно падать на OneToOne (IntegrityError) — редирект на существующий отклик — задача 11.
5. **Выпадашка компаний в VacancyForm** ограничена компаниями владельца; отправка чужого id компании — ошибка валидации, а не сохранённая строка — задача 11.
